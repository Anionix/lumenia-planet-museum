# 四つの層

| 層 | 記録するもの | 検査するもの |
| --- | --- | --- |
| 資料 | 人物、作品、制作の役割、出典と取得記録 | 識別子、根拠への接続、矛盾の保留 |
| 解釈 | 参照作品から選んだ形、色、動き、操作 | 人のレビュー。史実や美しさの証明にはしない |
| 数学 | 整数の反復、格子、角度、配色選択、状態 | Lean 4.28.0とWolframによる独立検算 |
| 描画 | Plumeriaが作るCSS、見え方、速度 | 今回は未接続。ブラウザーでの測定が必要 |

## 表現単位

人物15人に15個の初期レシピを用意する。人物とレシピは別の識別子を持ち、一人に複数のレシピを追加できる。
色は画像から測定したものではなく試作の選択値。陰影の白・黒は表面パレットと別の共通層。
「有機的0.9」のような数値例は今回の事実データへ移さない。

| 表現 | 決定論的な規則 | 限界 |
| --- | --- | --- |
| モリス | タイルを何周期ずらしても同じ位置、二度の反転で元へ戻る | 植物の細密描写や染色は対象外 |
| ミュシャ | 30度ずつの12スロット、全12方向が異なる | 等角は私たちの設計。十二宮の図像は同一ではない |
| マッキントッシュ | 格子に整列、順番の維持、反転 | 図柄を夫婦のどちらの仕事か勝手に断定しない |
| モンドリアン | 90度刻み、登録した色の範囲から選択 | 黒の格子を全生涯に一般化しない |
| リートフェルト | 数学上の面の法線が直交 | 透視投影後の画面上の角度は別 |
| ソットサス | 反復する面と45度刻みの小片 | 無秩序さや色数を美しさと同一視しない |
| バイヤー | 基準格子、円弧・棒の組合せ | 読みやすさ、既存書体の再現は対象外 |
| ミューラー＝ブロックマン | 整列した格子の間隔と順序 | 実際の文字組みの合格は別検査 |
| ヴィネッリ | 45度刻みの線、色の選択範囲 | 使える路線図ではない。共同制作を記録する |
| ラムス | 共通寸法の繰り返し | 中性色だから機能的、とは判定しない |
| 深澤直人 | 二度切り替えると元の再生状態に戻る | 自然な操作と感じるかは人が確認する |
| 川久保玲 | 左右の折り幅が必ず異なる | 布の物理や造形的な評価は未証明 |
| チャールズ・イームズ | 登録パレット、色成分の混合範囲 | 木・革・金属の物理特性は対象外 |
| レイ・イームズ | 格子、配色選択、色成分の混合範囲 | 特定の試作と共同製品の作者を分ける |
| グロピウス | 格子と直交する面、混合範囲 | ガラス風の陰影と実際のガラスを分ける |

## 入力と境界

### 最初から1〜4次元で計算する

計算の芯は任意の自然数を添えた`Coordinates dimension`。座標数を型に持たせる。
外部の入口は1〜4個の空間軸を受け付ける。座標は符号付き整数の格子単位で、
`coordinateUnit = integerGridUnit`を明記する。画面に渡す時だけ1〜64ピクセルの倍率を指定する。

| 空間次元 | 入力例 | 画面への投影 | 第一平面の90度回転 |
| --- | --- | --- | --- |
| 1 | `[4]` | `[4, 0]` | 第一平面がないため`null` |
| 2 | `[1, 2]` | `[1, 2]` | `[-2, 1]` |
| 3 | `[1, 2, 3]` | `[1, 2]` | `[-2, 1, 3]` |
| 4 | `[1, 2, 3, 4]` | `[1, 2]` | `[-2, 1, 3, 4]` |

`SpatiotemporalSample 3`は空間3軸とミリ秒の時刻を持つ。`Coordinates 4`とは別の型で、
時刻を第4空間軸へ暗黙に変換しない。各次元専用の別実装へ分裂させず、同じ再帰的な座標演算を使う。
4次元空間を回すことと、3次元の形を時間で動かすことは別の演算として追加できる。

外部要求は`operation / spaceDimensions / components / appendedAxis / timeMilliseconds / coordinateUnit`の6項目。
座標と追加する軸は−1000000〜1000000の整数、時刻は0〜120000000ミリ秒。
長さの不足・超過、未知項目、単位の違い、文字列、小数を拒否する。Leanの座標用入口もこの制約を確認する。
座標の追加と除去の復元、符号を含む回転の4回復元、投影の情報損失を証明・検算する。
`compileSpatialPlacement`は検査済みの投影へ明示した倍率を掛け、Plumeriaへ渡せるCSSの位置指定を返す。
画面の同じ位置へ写ったことを、元の形の同一性や人物の関係の根拠にしない。

この段階の座標は整数格子。任意角の三角関数、透視除算、浮動小数点の誤差、GPU描画は対象外。
CSSの4×4変換行列は3次元変換を表す同次座標であり、空間4軸の型と同一視しない。
参照：[W3CのCSS変換仕様](https://www.w3.org/TR/css-transforms-2/)、
[Wolframの行列累乗](https://reference.wolfram.com/language/ref/MatrixPower.html)。

### 表面レシピの値

`RawMaterialParameters → Option ValidatedMaterialParameters`。
繰り返し1〜64、格子間隔1〜64ピクセル、周期1000〜120000ミリ秒、候補層数1〜32、
不透明度0〜100%、パレット2〜8色。すべて整数で、これらの上限は作品史上の事実ではなく試作の方針。
候補層数は次の描画工程への予約値であり、現在のCSS断片の実ノード数や性能の証明ではない。

JavaScriptの外部入口は未知の項目、欠損、文字列の数値、負数、小数、非有限数、過大な整数を拒否する。
LeanのJSON入口は必要項目・型・数学上の制約を確認する。未知項目とJavaScriptの安全整数制限は外側の責務。
比較対象のインデックス・種は1000000以下、経過時間は120000000ミリ秒以下。
Leanの普遍定理自体はこのサンプルの上限に制限されない。

整数の色混合は `(100 − weight) × first + weight × second`、分母100。
0〜255の成分と0〜100の重みから0〜25500の分子を得る。知覚上の均一性・ガンマ補正は証明しない。
周期0に対するLeanの剰余は定義されるが、受理される描画用周期は必ず正。

## 知識の関係

Entity、Claim、Evidence、Source、取得記録を別にする。
主張レコードと証拠はUUIDv7。主張の定義・人物・資料・定理はUUIDv5で同じ意味を追跡する。
内部識別子を外部サイトの識別子へ置き換えない。
Wikidataの名前・説明の一致確認は作品解釈の裏づけではない。検索リンクは未同定の入口として残す。

主張は `asserted / inferred / disputed / unknown`、根拠は `supports / contradicts / neutral`。
保存済みの`asserted`は資料を読んだエージェントの記録であり、歴史的真実の認証ではない。
証拠の件数は検索ヒット数ではなく、その主張に接続した根拠の件数。
矛盾があれば`fail`、支持も反証もなければ`blocked`、改訂が違えば`staleEvidence`。
複数の機関が同じ説明を転載していても、独立した複数証拠とは自動的に数えない。
視覚的な距離から作れる関係は`sharesVisualFeatureWith`だけ。
`earlierThan`から`caused`、`cites`から`supports`、同時代から共同制作への自動変換は定義しない。

## Plumeriaへの受け渡し

生成する`MaterialSphere.styles.ts`はモジュール最上位の`css.create()`とリテラルだけ。
利用側は`import '@plumeria/core'`を行い、`classStyle={[...]}`で共通の球、模様、最後の陰影を別要素へ適用する。
入力にあるCSS文字列は受け付けない。画像・SVG・Canvas・Three.jsへ変換する分岐も持たない。
これは静的な表面の出力。動き・再生ボタン・動きを抑える設定は別契約であり、まだ画面につながっていない。
生成コードの型検査だけでPlumeriaのビルドやゼロランタイムの検査を代用しない。
初期パラメーターは提案であり、人物らしさの視覚確認前に完成品として出荷しない。

## 検査と報告

`node planetarium/scripts/check.mjs`は意図・仕様・人物情報を読み、Lean構築、公理依存、
Lean実行体とJavaScriptの入出力、無効入力、資料への接続、生成スタイルの型を検査する。
演算担当はLeanの証明とWolframの独立計算に分け、統合担当が同じ入力契約・現在のソース改訂へ結び付ける。
言語サーバーは構築、診断、未完了ゴール、型、構造、公理依存を実際に取得する。
Wolframでは数式と有限の例を独立に計算し、生の応答・入力・改訂を保存する。
Wolframや言語サーバーの受領記録は作成前後のソース改訂が一致しない限り採用しない。
全ゲートに観測値、基準、単位、使用ツール、改訂、UUIDv7、失敗理由を持たせる。
`pass / fail / blocked / staleEvidence`以外を合否値に使わない。
