## 結果と範囲

線・面・立体の表示と操作はChromeで合格。厳密な三次元モデルや物理的な照明計算は要求しない。線48本、半透明の帯24本、不透明な面288枚をCSSで配置する。作品の描画にSVG・Canvasを使わず、Three.js・glTF・復号器も配信物に含めない。サイトの小さな識別画像は描画処理とは別である。参考資産の検証工程は別系統として保管する。

Build Web Appsの手順を用いた。検査する流れは「各作品を開く → 自動回転 → 停止 → 速度変更 → 初期化 → ドラッグ → 再生」。アプリ内ブラウザーで最新版の切り替えと再生状態を確認した。アプリ内ブラウザーの全体画像に寸法の不整合があったため、画像と詳細測定には独立したPlaywrightのChrome画面を用いた。停止テストに利用者の画面を使っていない。

Chrome 153.0.8010.36、1499×1049、表示倍率1、携帯幅390×844。ローカルの127.0.0.1:4173、初回キャッシュなし、Brotli圧縮配信、回線・処理速度の人工制限なし。単一標本の診断であり、公開環境の性能保証ではない。

## 参照画像との照合

参照画像と最新版の六枚の実画面を `view_image` で直接確認した。画面の構成・見た目は追加指示を反映した表示仕様に沿って確認済み。静止した生成画像との画素単位の同一性は主張しない。

| 照合点 | 参照 | 実画面・対応 |
|---|---|---|
| 画面構成 | 名前、見出し、四段階の選択、中央作品、操作、記録 | 同じ順序と枠のない構成を維持 |
| 見出しと表示文 | 光のかたち／触れる。動く。軽さを確かめる。 | 一致。不要なラベルを追加していない |
| 文字の大小 | 大きい見出しと控えめな補助表示 | 見出し56画素、携帯幅34画素。システムフォント使用は通信予算を優先した既定の違い |
| 色と区切り | 暗い背景、明るい文字、黄緑、細い線 | 同じ色の規則と区切りを維持 |
| 作品の描き方 | 線の輪による奥行き | 指示に合わせCSSの線・半透明の帯・不透明な面へ変更 |
| 立体のつなぎ目 | 閉じた輪の印象 | 面の外側まで幅を確保し、三角形の黒いすき間を解消 |
| 操作列 | 停止・初期化・速度・ドラッグ案内 | 同じ操作名を維持。49画素のボタンを確認 |
| 携帯幅 | 同じ表示要素を読みやすく配置 | 横はみ出しなし。作品・操作・下部リンクが重ならない |
| 動き | 回転と利用者の操作 | 三作品ともCSSの連続回転。利用者へ返す画面は再生中 |

表示文の差分: 下部の描画方式を「Plumeria / CSS」に統一した。画像内の「再生」は停止後の検査状態で、通常は「一時停止」。参照の形を静止画像として再現するのではなく、利用者が指定したCSS表現を採用した。新しい「参考資産の報告」は検算記録ページだけに配置し、現在の作品とは別系統であることを明示した。
